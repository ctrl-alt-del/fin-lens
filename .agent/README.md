# .agent/ — 工作流技能（不是运行时）

这个目录放的是**操作员视角的工作流**：一个 Agent 在什么情况下、按什么顺序、
用哪些命令去驱动 FinLens。它不参与产品运行——估值引擎是 Rust 二进制，
在 `src/domain` 与 `src/service.rs` 里，确定性、可单测，不需要也不应该"被 skill 化"。

接入自己的组合先读 `docs/onboarding.md`；私有数据边界见 `docs/private-data.md`。

## 为什么这样切

| | 运行时引擎（Rust） | 工作流技能（本目录） |
|---|---|---|
| 输入 | 数据库行 + 行情映射 | 人的意图 + 仓库状态 |
| 输出 | 净值估算 / 穿透报告 | 一次有验证的操作 |
| 要求 | 确定性、毫秒级、可回归测试 | 可读、可审计、失败可恢复 |
| 变了会怎样 | 改估值口径，必须配单测 | 改操作顺序，必须配验证命令 |

把估值公式写进 prompt 会失去三样东西：单测、复现性、延迟。
反过来，把"盘后先刷新再验证、验证完看误差归因"这种判断留给模型，
每次都可能漏步骤。所以边界是：**引擎确定性，工作流技能化。**

## 技能清单

| 技能 | 触发场景 | 会写状态吗 |
|---|---|---|
| `market-refresh` | 盘前、快照过期、种子变更后 | 写 `seeds/`、SQLite |
| `daily-validation` | 净值公布后（约 20:00–23:00 CST） | 写 `data/daily/`、`calibration` |
| `onboard-fund` | 新增/替换基金 | 改 `funds_source.json`、重生成种子 |
| `dashboard-triage` | 用户问"今天怎么样/有没有异常" | 只读 |
| `dashboard-brief` | 用户要一段可转述的今日简报 | 只读；不重算、不改数据 |

## 技能写法

每个 `SKILL.md` 必须有四段：

1. **何时用** —— 触发条件，含"不该用"的情况。
2. **步骤** —— 可复制粘贴的命令，顺序不能换。
3. **验证** —— 怎么确认这步真的成了（查库/查接口，不靠"看起来对"）。
4. **失败处理** —— 常见断点与不要做的事（例如快照缺失时不要伪造 0%）。

## 给 Agent 的总规则

- 先读根目录 `AGENTS.md` 的硬约束，再执行技能。
- 任何写操作前先 `git status --short`，避免把生成物和手工改动混在一起。
- 命令统一在仓库根目录执行；cargo 前 `export CARGO_HOME="$PWD/.cargo-home"`。
- 不要在提示词里让模型"估算一个大概的净值"——所有数字必须来自命令输出或 API。

## 兼容性

这些文件是纯 Markdown + YAML frontmatter，Claude Code、Codex、DSH 等都可以直接读。
DSH 若要从工作区加载，可把 `.agent/skills/<name>` 链接到 `.dsh/skills/<name>`；
本仓库不预置 `.dsh/`，避免把某一种 Agent 运行时的目录写进版本库。
